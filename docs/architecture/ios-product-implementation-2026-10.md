# iOS 主要功能实施计划（2026-10-10）

## 目标与已确认约束

建立用户可操作的仓库导入／扩展安装 → 浏览／详情 → 漫画、小说阅读与视频播放 → 收藏、历史、更新检测闭环。
本轮沿用已经验证的 Mihon、Aniyomi、Tsundoku、JAR 与 CMS；不扩大生态测试范围。
界面全部使用原生 SwiftUI，平台图像解码与播放器使用 Apple 原生能力；阅读语义复用 `reader-core`。
保留 Android 主要功能，翻译、OCR、翻译日志暂不迁移。超分、WebView 兼容、真机 JVM 和分发独立验收。
接手时工作区已有 Claude 的未提交改动；不创建分支、不提交、不丢弃既有工作。

## 模块与生命周期

- `core-library`：从已有桌面持久化实现提取跨平台漫画库与更新检测，复用共享 Room 和 core-domain 规则；
  桌面保持源码接口兼容，iOS 仅消费投影，不另建收藏／历史数据库。
- `ios-shared`：装配共享漫画库、仓库索引与 reader-core，保留完整 Source DTO 和 64 位身份。
- `source-host`：扩展导入／转换／校验／注册使用现有进程会话，不销毁重建 Mobile 兼容平台。
- SwiftUI：应用级数据库与源会话；子页面借用会话。阅读画布与控件面板的生命周期独立。

## 实施阶段与验收

1. **记录闭环**：收藏增删／分类、历史、漫画／小说／视频进度记录与恢复、收藏更新检查及失败报告。
   验收共享持久化与重开测试，原生详情和库入口的 UI 测试。
2. **仓库与安装**：识别 `kototoro://add-repo?url=…&kind=…`，支持粘贴与系统打开；复用 JSON／Protobuf
   索引解码，持久化仓库记录；用户选择 APK／JAR，设备端转换与 SHA／身份校验后安装，支持重启恢复。
   JVM 的动态注册沿用 registry replace 与租约，不关闭仍在使用的源。
   验收 repo-hub 的五种链接、无效地址／重复记录、转换失败保留旧安装、装入后枚举和重启恢复。
3. **共享阅读引擎**：分页／连续场景、缩放与平移、宽页拆分／双页、可见页进度和预读；图像在原生层
   解码，保持源客户端请求及沙盒 artifact 校验。超长页分块和内存预算单独测试。
4. **原生阅读控件**：章节胶囊变形为章节面板；右上更多变形为选项面板；两者互斥，关闭回到原入口。
   章节保留章节／页面／书签、分支、搜索、排序、列表／网格、筛选与多选操作；更多分为快捷动作、布局、
   显示、控件和设置。底栏为独立的上一章图标按钮／可拖动页进度条／独立的下一章图标按钮，
   三者不共用背景，不额外显示上一页和下一页。
   书签为可选的右下浮动按钮，悬在下一章按钮上方，浮动控件最多四个。支持减少动态效果与辅助功能。
5. **最终验证**：默认原生 CMS 构建及可选 JVM 模拟器构建、共享测试、确定性 fixture 的端到端闭环；
   对照已测试源做针对性回归。记录真机／分发、源特定高级功能和后台调度的实际未验收范围。

- 真机 JVM 与签名／分发仍未验收；扩展安装需要可选 JVM 构建，默认原生构建支持 CMS。
  真机 `iosArm64` 原生切片与 `KototoroShared.xcframework` 编译已通过，但不替代真机运行验收。

- 更多与章节面板已经具备原生布局和核心操作，仍需真机辅助功能、iPad／横屏及长章节性能验收。
